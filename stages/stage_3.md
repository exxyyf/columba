# Этап 3. Сабмит и агрегация (промежуточная сдача)

**Цель:** настоящий (не нулевой) сабмит: `run_inference` и CLI собирают
`quality_class`/`quality_prob`/`violation_type` из чекеров позвоночника
через новый агрегатор, с честной константой-приором для бедра (чекеров
бедра ещё нет — этапы 4–5) и метриками с ДИ на реальной разметке.
Обучения на этапе нет — только агрегация уже посчитанных скоров. Этап
выделен отдельно, потому что это ворота автопроверки: полярность меток,
посимвольные строки словаря и формат файла должны быть закрыты тестами
до любого улучшения моделей.

## Агрегатор и маппинг флагов

`aggregate.aggregate_predictions` — реализация интерфейса `Predictor`,
подключается в `run_inference` через сентинел `predictor=AUTO`; явный
`predictor=None` по-прежнему даёт «нулевой» сабмит (для тестов формата).
Маппинг чекер → строка словаря — только через
`config.OUTPUT_LABELS_BY_REGION`, без строковых литералов; порядок типов
в `violation_type` — фиксированный порядок словаря, не порядок
срабатывания чекеров. `quality_class` = OR по флагам чекеров региона;
агрегатор не пересчитывает пороги и не трогает скоры — флаг берётся из
чекера как есть.

## Политика `not_evaluated`

Чекер без скора трактуется как «нарушения нет»
(`NOT_EVALUATED_TREATED_AS_VIOLATION = False` — именованная константа,
чтобы решение было явным и пересматриваемым), ключ чекера фиксируется в
отладочной колонке `not_evaluated_checkers` — информация не теряется,
даже когда на решение не влияет. На train `not_evaluated` — ноль случаев;
политика существует для закрытого теста.

## `quality_prob`: сигмоида вокруг порога, выбор scale

До калибровки этапа 6 `quality_prob` файла = `max` по
`sigmoid((score − threshold) / scale)` среди чекеров региона со статусом
`ok` (максимум, а не среднее — иначе слабые сигналы разбавляли бы явное
нарушение). Скор оси уже беззнаковый (`abs(angle)`) — повторный `abs()`
не нужен, отмечено в докстринге.

**Выбор scale** — три варианта на train-скорах:

1. IQR/1,35 по train-негативам — вырождается: у укладки медиана дефицита
   негативов ровно 0,0, scale ≈ 0, сигмоида превращается в ступеньку.
   Отвергнут.
2. std одних train-негативов — слишком узкий scale, сигмоида насыщается.
   Отвергнут.
3. **std всех train-скоров (негативы + позитивы) — принят**: единственный
   вариант без вырождения и с приемлемым насыщением (доля строк с
   `|prob − 0.5| > 0.48` — 0–1,25% по чекерам).

Итог: `spine_axis` 1,2747°, `spine_positioning` 0,2047,
`spine_objects` 0,3400. Отступление, исправленное на ревью: первая версия
считала scale по всем 99 снимкам (train+val) — утечка вала в калибровку;
исправлено на train-only, числа выше — уже исправленные.

Согласованность на границе порога: у укладки/предметов сравнение
нестрогое (`score >= threshold`) — на пороге `flag=True` и `prob = 0.5`
ровно; у оси строгое (`score > threshold`) — инвариант «class 1 ⇒ prob ≥
0.5, class 0 ⇒ prob ≤ 0.5» выполняется с равенством только на самой
границе, тесты проверяют точки чуть выше/ниже.

## Бедро до этапа 4: честный приор

Все файлы бедра получают `quality_class = 0`, пустой `violation_type` и
`quality_prob = HIP_PRIOR_QUALITY_PROB = 34/122 ≈ 0.279` — доля нарушений
бедра на train-фолде. Не 0,0: бинарный ROC-AUC считается по всем файлам
сразу, и искусственно «уверенные» нули у целого региона портили бы
ранжирование против позвоночника; константа даёт бедру нейтральное, но
согласованное с базовой частотой ранжирование.

## Дубликаты и CLI

Отдельного кэша в агрегаторе нет: он построчно детерминирован по колонкам
чекеров, а у копий одного `pixel_hash` эти колонки уже идентичны (кэш
этапа 2) — три копии дают три одинаковые строки, проверено тестом.
CLI `uv run python -m columba.submit <input_dir> <output.csv>` печатает
сводку (файлы, регионы, типы нарушений, время) и сообщает об ошибках
входа без трейсбека.

## Оценка этапа

Отступление от плана, согласованное на ревью: вместо двух отдельных
прогонов пайплайна (для метрик и для сабмита) — общая функция
`submission_from_manifest` в `inference.py`, которую вызывают и
`run_inference`, и `stage3_eval.py`; манифест считается один раз (прогон
ускорился с ~100 до 45 с). Связывание с таргетами — по `pixel_hash`.
Метрики реализованы на numpy/pandas без добавления sklearn в зависимости
(ROC-AUC через ранговую формулу, F1 вручную). F1 типа без истинных
позитивов в срезе — `NaN`, Macro-F1 — среднее по типам с определённым F1
(порядок подсчёта у организаторов неизвестен — вопрос задан).

**Метрики** (уникальные изображения; `artifacts/stage3_report.md`):

| Срез | Бинарная F1 | ROC-AUC | Macro-F1 (4 типа) |
|---|---|---|---|
| train (202/60 позитивов) | 0,385 [0,247; 0,523] | 0,571 [0,488; 0,66] | 0,332 [0,202; 0,439] |
| val (47/12) | 0,40 [0,0; 0,667] | 0,573 [0,35; 0,815] | 0,367 [0,0; 0,6] |
| all (249/72) | 0,387 [0,253; 0,505] | 0,572 [0,487; 0,654] | 0,338 [0,225; 0,424] |

По регионам (all): позвоночник — F1 0,692, AUC 0,797; бедро — F1 0,0,
AUC 0,5 (константа приора — предсказуемо неинформативное ранжирование
внутри региона).

**Sanity-проверка:** функция метрик на эталонном сабмите из истинных меток
(`submission_reference.csv`) даёт 1,0 по всем метрикам — корректность
самой функции метрик подтверждена отдельно от качества пайплайна.

### Выводы

1. **Узкое место — бедро**: 36 из 42 позитивов «Некорректной укладки» и
   все 7 «Некорректной области интереса» — бедро; пока чекеров бедра нет,
   вклад региона в эти строки — только FN. Этап 4 даёт наибольший
   ожидаемый прирост.
2. **Общий ROC-AUC 0,57 ниже, чем у одного позвоночника (0,80)** — не
   из-за качества чекеров, а из-за константы приора бедра, воткнутой
   посреди распределения вероятностей позвоночника: межрегиональная
   согласованность `quality_prob` — задача калибровки этапа 6.
3. Агрегация ничего не растеряла: F1 позвоночника совпадает с рабочей
   точкой этапа 2 в пределах округления.

## Тесты

155 зелёных (118 прежних + 37 новых): полярность, посимвольная сверка
словаря, отсутствие типов чужого региона, строка на каждый файл (включая
дубликаты и Failure), идентичность предсказаний дублей, `not_evaluated`
без исключений, приор бедра, согласованность class/prob у порога,
монотонность `quality_prob` по скору, sanity = 1,0, CLI пишет валидный
файл, сабмит не меняется при вырезанных тегах и переименованных файлах.

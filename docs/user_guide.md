# Руководство пользователя

Как проверить пачку DXA-исследований и прочитать результат. Предполагается,
что сервис уже запущен (см. [deployment.md](deployment.md)) и отвечает на
`http://localhost:8000` — далее все примеры используют этот адрес.

## Быстрая проверка, что сервис готов

```bash
curl http://localhost:8000/health
```

Ответ показывает устройство инференса (`cpu`/`cuda`/`mps`) и наличие каждого
файла весов:

```json
{
  "status": "ok",
  "device": "cuda",
  "seed": 42,
  "weights_loaded": {
    "region_cnn": true,
    "spine_keypoint_unet": true,
    "spine_objects_cnn": true,
    "hip_positioning_cnn": true
  }
}
```

Если `hip_positioning_cnn` равен `false`, тип «Некорректная укладка» для
бедра выставляться не будет (см. «Частые вопросы» ниже) — скачайте веса по
[WEIGHTS.md](../WEIGHTS.md) и перезапустите сервис.

## Способ 1: веб-интерфейс

Откройте <http://localhost:8000/> в браузере.

1. **Загрузите исследования** одним из трёх способов:
   - отдельные `.dcm`-файлы (кнопка выбора файлов, можно несколько сразу);
   - папку целиком — структура подпапок сохраняется, поэтому стороны пары
     бёдер одного пациента разводятся парно;
   - ZIP-архив каталога (та же структура, что примет `/predict/zip`).
2. **Дождитесь таблицы результатов.** Для каждого файла: имя, регион, класс
   качества, вероятность нарушения и перечень типов. Над таблицей — сводка по
   пачке (всего файлов, сколько с нарушениями, разбивка по типам, время).
3. **Посмотрите визуализацию**: кнопка «Визуализация» в строке показывает
   кадр с найденными ориентирами (центры тел позвонков и ось; головка,
   вертелы и ось диафиза у бедра) и результатами каждого чекера.
4. **Выгрузите CSV** кнопкой экспорта — файл в точности повторяет формат
   ответа `/predict`.

Интерфейс не сохраняет файлы на сервере между запросами: всё считается в
момент загрузки во временном каталоге.

## Способ 2: пакетная проверка через API

Основной сценарий — каталог с исследованиями упаковывается в ZIP и
отправляется одним запросом; в ответ приходит готовая таблица:

```bash
zip -r test_data.zip <каталог_с_исследованиями>
curl -F "file=@test_data.zip" "http://localhost:8000/predict/zip" -o submission.csv
```

Тот же результат в JSON (удобно для скриптов):

```bash
curl -F "file=@test_data.zip" "http://localhost:8000/predict/zip?format=json"
```

Плоский список файлов без архива:

```bash
curl -F "files=@CR000000.dcm" -F "files=@CR000001.dcm" \
  "http://localhost:8000/predict" -o submission.csv
```

Замечание: при плоской загрузке структура папок неизвестна, поэтому стороны
пары бёдер одного пациента определяются по каждому кадру независимо. Для
максимального качества отправляйте ZIP с папками исследований.

Визуализация одного файла:

```bash
curl -F "file=@CR000000.dcm" "http://localhost:8000/visualize" -o overlay.png
curl -F "file=@CR000000.dcm" "http://localhost:8000/visualize?format=json"
```

Вариант с `format=json` возвращает регион, сторону и результат каждого
чекера (скор, флаг, статус `ok`/`not_evaluated` с причиной, численные
сигналы) — это самый подробный источник для разбора конкретного файла.

## Как читать результат

Каждому входному файлу соответствует ровно одна строка (дубликаты тоже
получают свою строку):

| Колонка | Как читать |
|---|---|
| `file_name` | путь файла относительно корня загруженного каталога/архива |
| `anatomical_region` | «Поясничный отдел позвоночника» или «Проксимальный отдел бедра» — определяется по изображению |
| `quality_class` | **1 — найдено нарушение**, 0 — качественное исследование |
| `quality_prob` | вероятность нарушения от 0 до 1; согласована с классом (класс 1 ⇔ вероятность ≥ 0,5) |
| `violation_type` | конкретные типы нарушений через «;», пусто при отсутствии |

Типы нарушений: у позвоночника — «Некорректная укладка», «Не выровнена ось
позвоночника», «Присутствуют посторонние предметы»; у бедра — «Некорректная
укладка», «Некорректная область интереса».

Отладочные колонки (`read_status`, `dedup_group_id`, `study_folder`,
`sop_instance_uid`) помогают проследить судьбу файла: например,
`read_status ≠ success` означает, что DICOM не удалось прочитать — такой файл
получает класс 0 с нулевой вероятностью, а не выбрасывается из таблицы.

Альтернативный формат вывода — DICOM SR (Comprehensive SR) на каждый файл:

```bash
uv run python -m columba.dicom_sr <файл_или_каталог>
```

## Частые вопросы

**Пачка обработалась, но по бедру никогда не появляется «Некорректная
укладка».** Проверьте `GET /health`: скорее всего отсутствует файл весов
`hip_positioning_cnn.pt` — без него этот чекер честно отключён
(`not_evaluated`), а не работает молча хуже.

**В таблице появилось имя файла с суффиксом `__1`.** В одной загрузке
оказалось два файла с одинаковым именем (например, из разных папок при
плоской загрузке) — сервис автоматически развёл имена, ни один файл не
потерян.

**Сервис вернул 400.** В теле ответа указана причина: во входе нет
`.dcm`-файлов, архив не распаковывается или относительные пути недопустимы.
Исправьте вход и повторите — частичных результатов при 400 не бывает.

**Файл явно с нарушением, а класс 0.** Посмотрите
`/visualize?format=json` для этого файла: там видно, какой чекер что решил и
по каким сигналам, включая статусы `not_evaluated` с причинами.

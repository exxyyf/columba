## Принцип пайплайна

Не end-to-end чёрный ящик, а модульный пайплайн «детекция анатомических
ориентиров → геометрические правила». Причины: критерии качества DXA
измеримы, размеченных данных мало (252 уникальных изображения), а
объяснимость — прямое требование задачи; такой подход напрямую отвечает
на вопрос «какое именно нарушение».

## Сквозные конвенции (действуют со своего этапа и до конца)

- **Полярность:** `quality_class = 1` и `quality_prob` — это **нарушение**.
  Конвенция зафиксирована в `config` и закрыта юнит-тестом: перепутанная
  полярность обнулила бы обе метрики автопроверки.
- **Только пиксели.** Регион, сторона и все чекеры не читают DICOM-теги
  зоны и имена файлов (в закрытом тесте их не будет) — проверяется тестом
  с вырезанными тегами и нейтральными именами.
- **Анизотропия пикселя** (1,05 мм по Y, 0,6 мм по X — тега PixelSpacing в
  выгрузке нет, значения из документации аппарата): все углы и расстояния
  считаются в физических координатах, входы нейросетей ресемплируются к
  изотропному пикселю. Регэксп-тест запрещает дублировать литералы
  spacing вне `config`.
- **Все пороги и константы — в `config`**, единственном источнике истины.
- **Честная валидация.** Позитивов по отдельным критериям единицы, поэтому
  пороги и метрики оцениваются вложенной групповой кросс-валидацией по
  исследованиям (out-of-fold); val используется только как финальный смоук.
  Синтетические примеры никогда не участвуют в валидационных метриках.
- **Честная деградация.** Битые файлы получают статус `Failure` и строку в
  сабмите; чекер без данных отвечает `not_evaluated` с причиной, а не
  молчаливым нулём; отсутствие файла весов не роняет сервис.
- **Дубликаты** (попиксельные копии с разными SOP UID — артефакт выгрузки
  PACS) дедуплицируются только для обучения и сплита; в инференсе каждый
  файл получает свою строку, дубликаты обсчитываются один раз через кэш по
  хэшу пикселей.

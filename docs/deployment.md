# Руководство по развёртыванию

Как поднять сервис Columba на целевом сервере. Рекомендованный путь — Docker;
локальный запуск через `uv` описан в конце.

## Требования к хосту

| Ресурс | Минимум | Комментарий |
|---|---|---|
| CPU | 2 ядра | инференс ~0,08 с/файл на CPU — лимит «3 мин/исследование» выполняется с запасом и без GPU |
| RAM | 4 ГБ | |
| Диск | ~10 ГБ | GPU-образ с CUDA-колесом PyTorch занимает несколько ГБ; CPU-образ заметно меньше; веса моделей ~140 МБ |
| GPU | не обязателен | при наличии NVIDIA GPU нужны драйвер и `nvidia-container-toolkit` |
| Софт | Docker 24+ | для локального запуска вместо Docker — Python 3.12 + [uv](https://docs.astral.sh/uv/) |
| Сеть | не нужна в рантайме | интернет нужен один раз: скачать образы/зависимости и веса |

## Шаг 1. Веса моделей

Веса не хранятся в git и не запекаются в образ — они лежат в
`artifacts/models/` на хосте и монтируются в контейнер только для чтения.

На хосте с интернетом:

```bash
uv run python -m columba.weights download   # скачает по ссылкам из weights_registry.json
uv run python -m columba.weights verify     # сверит размеры и SHA-256, код выхода 1 при проблеме
```

На хосте без интернета: скачайте четыре файла по ссылкам из
[WEIGHTS.md](../WEIGHTS.md) на любой другой машине, перенесите в
`artifacts/models/` и выполните `verify` (он работает офлайн).

Сервис умеет стартовать и без части весов (честная деградация, матрица — в
[WEIGHTS.md](../WEIGHTS.md)), но контейнер по умолчанию требует полный
комплект — это защита от молчаливой потери качества на проверке.

## Шаг 2. Сборка образа

```bash
# вариант для сервера с NVIDIA GPU (по умолчанию; работает и на CPU)
docker build -t columba:gpu .

# облегчённый CPU-вариант (меньше образ, быстрее сборка) — для машин без GPU
docker build --build-arg TORCH_VARIANT=cpu -t columba:cpu .
```

`TORCH_VARIANT=cpu` пересобирает lock-файл внутри образа с CPU-колесом
PyTorch; файлы проекта на хосте не меняются. Оба варианта функционально
идентичны, отличается только наличие CUDA-рантайма.

## Шаг 3. Запуск

```bash
# GPU-сервер
docker run --rm --gpus all -p 8000:8000 \
  --mount type=bind,source="$(pwd)/artifacts",target=/app/artifacts,readonly \
  columba:gpu

# без GPU
docker run --rm -p 8000:8000 \
  --mount type=bind,source="$(pwd)/artifacts",target=/app/artifacts,readonly \
  columba:cpu
```

В PowerShell путь для `--mount` задаётся так:

```powershell
$artifactsPath = (Resolve-Path -LiteralPath artifacts).Path
docker run --rm -p 8000:8000 --mount "type=bind,source=$artifactsPath,target=/app/artifacts,readonly" columba:cpu
```

При старте контейнер выполняет `python -m columba.weights verify`: если
какой-то файл весов отсутствует или его SHA-256 не совпадает с
`weights_registry.json`, контейнер завершается с ошибкой **до** запуска
сервиса — причина видна в логах контейнера.

## Шаг 4. Проверка после запуска

```bash
curl http://localhost:8000/health
```

- `status` = `ok`, все четыре значения в `weights_loaded` = `true`;
- на GPU-сервере `device` = `cuda` (если `cpu` — см. «Устранение неполадок»).

Смоук-тест на реальном файле:

```bash
curl -F "files=@<любой>.dcm" http://localhost:8000/predict
```

Ожидается CSV со строкой на файл. Веб-интерфейс — <http://localhost:8000/>.

## Офлайн-гарантии

В рантайме сервис не делает ни одного внешнего сетевого вызова: он только
принимает файлы по HTTP и отвечает. Единственный модуль с сетевым кодом —
`columba.weights` (скачивание весов) — не импортируется ни инференсом, ни
сервисом, что зафиксировано тестом. Данные пациентов наружу не уходят;
загруженные файлы живут во временном каталоге только на время запроса.

## Обновление весов

1. Заменить файлы в `artifacts/models/` на хосте.
2. Убедиться, что `weights_registry.json` содержит их актуальные SHA-256 и
   размеры (при переобучении реестр обновляется процедурой из
   [training.md](training.md)).
3. Перезапустить контейнер — верификация на старте подтвердит комплект.

## Устранение неполадок

| Симптом | Причина и действие |
|---|---|
| Контейнер сразу завершился, в логах ошибка верификации весов | `artifacts/` не смонтирован, файл отсутствует или повреждён. Проверьте `--mount` и выполните `uv run python -m columba.weights verify` на хосте |
| `device: "cpu"` в `/health` на GPU-сервере | контейнер запущен без `--gpus all`, либо не установлен `nvidia-container-toolkit`/драйвер NVIDIA. Сервис при этом полностью работоспособен на CPU и укладывается в лимит времени |
| Порт 8000 занят | пробросьте другой: `-p 8080:8000` и обращайтесь к `localhost:8080` |
| Сборка GPU-образа слишком долгая/тяжёлая | для машин без GPU используйте `--build-arg TORCH_VARIANT=cpu` |
| HTTP 400 на `/predict/zip` | архив не распаковывается или в нём нет `.dcm`-файлов; пересоберите ZIP от корня каталога с исследованиями |
| Медленный первый запрос | при первом обращении загружаются веса моделей в память; последующие запросы быстрее |

## Локальный запуск без Docker

```bash
uv sync
uv run python -m columba.weights download && uv run python -m columba.weights verify
uv run uvicorn columba.service:app --host 0.0.0.0 --port 8000
```

Требуется Python 3.12 (uv поставит сам) и ~2 ГБ на окружение. На Apple
Silicon инференс автоматически использует MPS.

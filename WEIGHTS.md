# Веса моделей: контрольные суммы и внешнее хранилище

Веса лежат в `artifacts/models/` и в git не хранятся (каталог `artifacts/`
целиком игнорируется). Требование организаторов: модели можно хранить
отдельно со скачиванием, ссылки прикрепить заранее (пиковая нагрузка при
проверке).

Общая папка с весами:
[Google Drive](https://drive.google.com/drive/folders/1FCzOkP2ctIcGNbcxWpfyEX9Wd1G9_43O?usp=sharing).
Все четыре файла доступны без входа в аккаунт; скачивание и совпадение
размеров и SHA-256 с реестром проверены 2026-09-28.

Источник истины для автоматической загрузки — **`weights_registry.json`**
в корне репозитория (в отличие от `artifacts/`, этот файл коммитится в git).
Таблица ниже — его человекочитаемая проекция; при расхождении верить JSON.
Контрольные суммы
обновляются в JSON при каждом переобучении, ссылки вписываются туда же после
ручной загрузки в хранилище (заливка веса и правка `url` в реестре — ручное
действие команды).

## Проверка и загрузка

```bash
# Проверить sha256 всех присутствующих файлов, показать список отсутствующих
uv run python -m columba.weights verify

# Скачать веса по ссылкам из реестра (только те, для которых url вписан)
uv run python -m columba.weights download
uv run python -m columba.weights download region_cnn.pt   # выборочно
```

`verify` завершается с кодом 1, если файл отсутствует или не совпадает с
реестром. Контейнер выполняет эту проверку перед стартом сервиса: смонтируйте
`artifacts/` в `/app/artifacts` только для чтения.

Скачивание — во временный файл рядом с целью, проверка sha256, затем атомарное
перемещение; при несовпадении хэша или пустой ссылке файл не
создаётся и печатается понятная причина. `columba.weights` — единственный
модуль пакета с сетевым кодом (`urllib` из stdlib, без новых зависимостей);
инференс и сервис его не импортируют (проверяется тестом), так что
воспроизведение решения на закрытом тесте остаётся полностью офлайн.

## Честная деградация без каждого файла

Рантайм без весов не падает — модульная архитектура решения рассчитана
на это:

* **`region_cnn.pt`** отсутствует -> `load_region_predictor()` вернёт `None`,
  регион/сторона определяются чистой эвристикой по ширине кадра (300/280 px,
  подтверждена организаторами), `region_disagreement` всегда `False`
  (сравнивать не с чем); на нестандартной ширине кадра (не 300/280/248 px)
  региона не будет вообще — там приоритет у CNN, эвристика не определена.
* **`spine_keypoint_unet.pt`** отсутствует -> не влияет на рантайм: центры
  тел позвонков всегда ищет классический детектор (DP-хребет + максимумы
  профиля), U-Net в рантайм-пути `spine_checkers.py`/`inference.py` не
  подключена в принципе (используется только отдельным скриптом
  `spine_unet_check.py`) — это штатный режим, а не деградация.
* **`spine_objects_cnn.pt`** отсутствует -> решающий скор/флаг чекера
  «Присутствуют посторонние предметы» и без файла всегда rule-based (по
  вложенной CV правило точнее: OOF AUC 0.820 против 0.772 у CNN) — просто
  пропадает `signals["cnn_probability"]`; на `quality_class`/`quality_prob`
  не влияет.
* **`hip_positioning_cnn.pt`** отсутствует -> `check_hip_positioning` (`hip_checkers.py`)
  **всегда** возвращает `not_evaluated` (геометрия одна статистически не
  отличима от случайного, nested CV AUC 0.564 [0.452; 0.684] против 0.765 у
  CNN) — тип «Некорректная укладка» для бедра **никогда не выставляется**.
  Агрегатор (`_hip_row_prediction`, `aggregate.py`) берёт `quality_prob`/
  `quality_class` бедра только из `hip_roi` (если он `ok`), а если и
  `hip_roi` не оценён — откатывается на приор `HIP_PRIOR_QUALITY_PROB` с
  `quality_class=0`. Пайплайн не падает и формат сабмита не нарушается, но
  чекер укладки бедра фактически отключён, а не «работает хуже».

## Примечания

* Загрузка в хранилище — ручное действие команды; сделано для всех
  четырёх файлов (Google Drive). Все ссылки вписаны в `weights_registry.json`
  и реально проверены: `uv run python -m columba.weights download` (без
  аргумента — все сразу) скачивает и сверяет sha256 каждого. Подробности
  обхода предупреждения Drive о непроверенных антивирусом файлах —
  `stages/stage_9.md`, раздел «Веса и воспроизводимость». `region_cnn.pt`/
  `spine_keypoint_unet.pt`/`spine_objects_cnn.pt` изначально были обучены на
  другой машине (в реестре уже был их sha256) и не сразу попали в это
  хранилище — дозалиты позже.
* Seed 42 зафиксирован, но на MPS/CPU возможна библиотечная
  недетерминированность — после переобучения обновить sha256/размер в
  `weights_registry.json` и прогнать тесты (критерии качества проверяются
  тестами, не хэшем).

# Процедура обучения и дообучения моделей

Для инференса обучение не нужно — достаточно скачать готовые веса
([WEIGHTS.md](../WEIGHTS.md)). Этот документ описывает, как воспроизвести
обучение с нуля или дообучить модели на новых данных.

Все локальные шаги детерминированы: seed 42 зафиксирован по всему пайплайну
(`config.SEED`), пороги и константы живут в одном месте —
`src/columba/config.py`.

## Данные

Ожидаемая раскладка (в git не хранится):

```
data/
  НД_для_обучения/
    Исследования/<uid_исследования>/.../*.dcm   # DICOM-файлы, папка на исследование
    разметка.xlsx                               # лист «Калибровка»: 7 бинарных критериев + комментарии
  Для теста/*.dcm                               # опционально: смоук-выборка
```

Особенности разметки, которые учитывает пайплайн автоматически:

- таргеты собираются **только из столбцов критериев**; агрегатный столбец
  «Итог» игнорируется (содержит ошибки агрегации);
- пропуск в критерии означает «зона не снималась», а не «нет нарушения»;
- попиксельные дубликаты (разные SOP UID, одинаковые пиксели) схлопываются
  до сплита; матчинг с таблицей — по именам папок выгрузки.

## Шаг 0. Подготовка датасета

```bash
uv run python main.py
```

Собирает `artifacts/`: манифест всех файлов со статусами чтения и
dedup-группами, таргеты из критериев, стратифицированный по пациентам сплит
train/val (без утечки ни по изображениям, ни по пациентам), лог аномалий
матчинга и EDA-отчёт. Все последующие шаги читают эти артефакты.

## Шаг 1. CNN региона и стороны

```bash
uv run python -m columba.train_region_cnn
```

ResNet18, 3 класса (позвоночник / левое бедро / правое бедро). Веса —
`artifacts/models/region_cnn.pt`, отчёт с метриками по фолдам — рядом в
`region_cnn_report.json`.

## Шаг 2. Модуль позвоночника

```bash
uv run python -m columba.build_spine_annotations   # разметка центров тел (детерминированная)
uv run python -m columba.spine_objects_cnn         # CNN-ветка детектора предметов
uv run python -m columba.spine_keypoint_net        # U-Net кейпоинтов (артефакт сравнения, не в рантайме)
uv run python -m columba.spine_eval                # калибровка порогов + отчёт метрик
```

`build_spine_annotations` не требует ручного просмотра: точечные правки уже
зашиты в код. `spine_eval` строит `artifacts/spine_checker_report.md` —
вложенная CV, рабочая точка рантайма, проверки на синтетике.
Дисбаланс классов в `spine_objects_cnn` обрабатывается взвешенным лоссом
(`BCEWithLogitsLoss` с `pos_weight = n_neg / n_pos`).

Опциональные визуальные проверки: `spine_grids` (гриды позитивов),
`spine_unet_check` (устойчивость U-Net к маскированию + салиенси),
`spine_visualize` (примеры отработки чекеров).

## Шаг 3. Модуль бедра

Разметка ориентиров и экспорт обезличенного датасета кропов:

```bash
uv run python -m columba.build_hip_annotations
uv run python -m columba.hip_export     # -> artifacts/colab/hip_positioning_dataset.zip
```

Архив не содержит UID и тегов DICOM: исследования заменены обезличенными
идентификаторами `sNNN`, карта соответствия остаётся только локально.

Обучение CNN укладки бедра выполняется в Google Colab (GPU T4, ≤15 минут):

1. Залейте `hip_positioning_dataset.zip` на свой Google Drive.
2. Откройте [notebooks/hip_positioning_cnn.ipynb](../notebooks/hip_positioning_cnn.ipynb),
   укажите путь к архиву в первой ячейке и выполните Runtime → Run all.
   Внутри: ResNet18 (ImageNet-претрейн), 4-фолдовая групповая CV по
   исследованиям, взвешенный лосс + oversampling позитивов
   (`WeightedRandomSampler`) — дисбаланс сильный (29 позитивов на 122 train).
3. Скачайте результаты: `hip_positioning_cnn.pt` → `artifacts/models/`;
   `report.json`, `oof_train.csv`, `val_pred.csv` → `artifacts/`.

Калибровка порогов и отчёт:

```bash
uv run python -m columba.hip_eval    # -> artifacts/hip_checker_report.md
```

## Шаг 4. Агрегированные метрики и калибровка вероятности

```bash
uv run python -m columba.stage3_eval   # метрики сабмита на разметке -> artifacts/stage3_report.md
uv run python -m columba.calibrate     # Platt/изотоника на OOF-скорах, варианты порога -> artifacts/stage6_report.md
```

`calibrate` работает только на честных out-of-fold скорах (train-скоры
деплоя завышены утечкой — CNN бедра обучена на всём train) и выдаёт три
варианта порога класса с метриками и 95% ДИ. Перенос выбранной калибровки в
рантайм — осознанное решение: пороги фиксируются в `config.py` вручную по
отчёту.

## Шаг 5. Фиксация весов

После любого переобучения:

1. Обновите `size_bytes` и `sha256` соответствующей записи в
   [weights_registry.json](../weights_registry.json)
   (`shasum -a 256 artifacts/models/<файл>.pt`).
2. Залейте файл во внешнее хранилище и впишите `url` в реестр
   (ручное действие: из пайплайна внешние сетевые вызовы запрещены).
3. Проверьте комплект и инварианты:

```bash
uv run python -m columba.weights verify
uv run pytest
```

Тесты проверяют качество через пороговые критерии, а не через хэш весов,
поэтому библиотечная недетерминированность CPU/MPS при переобучении не
ломает их — но хэши в реестре обновить обязательно, иначе контейнер не
пройдёт верификацию на старте.

## Дообучение на новых данных

1. Добавьте новые исследования в `data/НД_для_обучения/Исследования/` и
   строки разметки в `разметка.xlsx` (те же 7 критериев).
2. Повторите шаги 0–5. Дедупликация, таргеты и сплит пересоберутся
   автоматически; пороги чекеров пересчитайте по свежим отчётам
   `spine_eval`/`hip_eval`/`calibrate` и зафиксируйте в `config.py`.
3. Обратите внимание на редкие классы: «Некорректная область интереса»
   калибруется на единицах примеров — при появлении новых позитивов стоит
   пересмотреть выбор решающего сигнала (см. отчёт `hip_eval`).
4. Прогоните `uv run pytest`: инварианты формата, полярности меток и
   отсутствия утечки в сплите проверяются автоматически.

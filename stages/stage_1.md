# Этап 1. Классификатор региона и стороны

**Цель:** безошибочное определение «поясничный отдел / бедро» (и стороны
бедра для внутренних нужд) только по изображению: эвристика по ширине
кадра, подтверждённая организаторами, плюс лёгкая CNN как страховка на
случай нестандартных кадров закрытого теста.

## Хвосты ревью этапа 0

- **`read_dicom` и force=True.** Первая попытка чтения — `force=False`;
  при неудаче — вторая с `force=True`, результат принимается только если
  пиксели реально декодировались. В отчёт об ошибке идёт исключение первой
  попытки — оно описывает файл честнее. Покрыто тестами: файл со срезанным
  128-байтным преамбулом читается, мусор и пустой файл — по-прежнему
  `Failure`.
- **Плоский каталог и латеральность.** Парное разведение сторон («больший
  score — правое») применяется только внутри папки исследования, где два
  бедра гарантированно одного пациента. В плоском каталоге пары не
  строятся: сторона — абсолютный знак признака, метод честно пишется
  `content_only`. Абсолютный знак согласован с парным разведением на всех
  151 бедре трейна, так что качество не падает.
- **`stratified_by` в `split.json`** приведён к фактическим токенам
  стратификации.

## Версии софта денситометра: 18.41.005 против 18.50.082

Вопрос, от которого зависело, нужна ли отдельная нормализация или
стратификация по версии. Сравнение по 252 уникальным изображениям
(193 против 59; версии не смешиваются внутри исследования):

- **Интенсивности**: разрядность (8 бит), фотометрия (MONOCHROME2),
  диапазон (0…252) идентичны; гистограммы переднего плана совпадают
  (относительное L1-расхождение 0,06).
- **Размеры кадров**: те же стандартные ширины 300/280; кадры 248 px
  (протокол эндопротеза) встретились только в 18.50.082 — единичный
  случай, не свойство версии.
- **Доли нарушений**: 27% против 35%; z-тест — общая разница не значима
  (p = 0,24). По `hip_positioning` на уровне изображений p = 0,003, но
  правое и левое бедро одного пациента сильно скоррелированы, и на честной
  единице — исследовании — сигнал не значим (25,8% против 50,0%,
  p = 0,062). Разнонаправленное отклонение `spine_objects` указывает на
  различия потока пациентов, а не софта.

**Вывод: отдельная нормализация и стратификация по версии не нужны**;
CNN обучается на объединённой выборке. Расчёт оформлен воспроизводимым
скриптом `columba/compare_software_versions.py` (отчёт —
`artifacts/eda/software_versions_report.md`). Пометка на этап 6: проверить
устойчивость метрик `hip_positioning` по версиям — выполнено на этапе 4,
риск снят.

## Датасет и обучение CNN

- 252 уникальных изображения, классы: spine 99 / hip_left 79 /
  hip_right 74; метки — из эвристики этапа 0. Спорные кейсы просмотрены
  вручную: эндопротез правого бедра (эвристика стороны верна) и оба кадра
  248 px (стороны сверены визуально; включены в датасет как
  hip_left/hip_right).
- Ресемплинг к изотропному пикселю — растяжение по Y в 1,75 раза, затем
  вписывание в квадрат 224×224 с сохранением пропорций. Литералов spacing
  в коде нет (контролируется тестом этапа 0).
- ResNet18 с ImageNet-предобучением, 3 класса; AdamW, lr 3e-4, 12 эпох,
  batch 16, seed 42. Аугментации: повороты ±5°, яркость/контраст ±10%,
  горизонтальный флип — **только с одновременным переключением метки
  стороны** (закрыто юнит-тестом на инволюцию).
- Результат: train/val accuracy 1,0; на всех 252 уникальных изображениях
  (и через хэш — на всех 499 файлах) регион и сторона совпадают с
  эвристикой, расхождений ноль.
- **Проверка маскирования**: Grad-CAM на 6 бёдрах с наибольшей площадью
  маскирования — активация сосредоточена на головке/шейке/вертелах, а не
  на краях чёрных прямоугольников; юнит-тест: синтетическое маскирование
  углов кадра не меняет предсказание.
- Инференс CPU-приемлемый: ~0,8 с/исследование вместе с чтением DICOM.

## Правило арбитража эвристика ↔ CNN

Реализовано в `region_cnn.arbitrate_region`:

1. **Стандартная ширина кадра (300/280/248 px)** — эвристика первична
   (подтверждена организаторами), CNN подтверждает; расхождение —
   предупреждение в лог + флаг `region_disagreement`, приоритет у
   эвристики. Ширина 248 px отнесена к стандартным: протокол эндопротеза
   наблюдался в трейне, регион известен — бедро.
2. **Нестандартная ширина** — эвристика не определена, приоритет у CNN.
3. **CNN недоступна** (нет весов) — чистая эвристика с фолбэком
   `unknown → hip`.

Дополнение по ревью этапа — **backfill стороны**: для 248 px эвристика
сторону не считает, а она нужна модулю бедра для ориентации кропов. Если
эвристика сторону не дала, а CNN доступна, сторона заполняется из CNN
(заполнение вакуума, не конфликт веток — `disagreement` не поднимается;
заданную эвристическую сторону CNN не перебивает). Без CNN сторона честно
остаётся пустой.

## Интеграция и репетиция закрытого теста

`describe_inputs`/`run_inference` получили параметр `region_predictor`:
`"auto"` (CNN подхватывается, если веса на месте), `None` (только
эвристика), экземпляр предиктора. Дубликаты обсчитываются CNN один раз —
кэш по хэшу пикселей (тест со счётчиком вызовов). Репетиция закрытого
теста (вырезанные теги, нейтральные имена, плоский каталог) прогнана
обеими ветками — ответы идентичны и верны, сабмит валиден.

## Итог этапа

89 тестов (67 этапа 0 + 8 хвостов ревью + 14 новых); тесты CNN
пропускаются при отсутствии весов. Артефакты: `region_cnn.pt` (веса +
классы), отчёт метрик по фолдам, Grad-CAM-проверка маскирования. Веса
выгружаются во внешнее хранилище (реестр — с этапа 9 в
`weights_registry.json`/`WEIGHTS.md`).

## Интерфейс просмотра датасета (`interface/`)

Вспомогательный просмотрщик снимков на TypeScript: галерея всех DICOM из
`data/` с автоопределением региона и стороны. Ключевые решения:

- **Классификация не дублируется.** Node-сервер вызывает bridge-скрипт
  `interface/bridge/describe.py`, который зовёт
  `columba.inference.describe_inputs` (эвристика + CNN + арбитраж) — на
  экране ровно то, что решает пайплайн; UI и логика не могут разойтись.
- Каталоги сканирования — по умолчанию `data/НД_для_обучения/Исследования`
  и `data/Для теста`: сканировать от корня `data/` нельзя, иначе все бёдра
  слиплись бы в одну «папку исследования», ломая парное разведение сторон.
- Рендеринг DICOM на TS — только для отображения; анизотропия учитывается
  при отрисовке, значения приходят из `columba.config` через bridge,
  литералов 1.05/0.6 в TS нет.
- Проверено на живых данных: 502 файла, позвоночник 167, бедро 335
  (170 лев. / 165 прав.), расхождений веток нет — совпадает с прогоном
  `describe_inputs` напрямую.

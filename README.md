# Columba — контроль качества DXA-исследований

Columba автоматически оценивает качество рентгеновской денситометрии (DXA):
принимает DICOM-файлы поясничного отдела позвоночника и проксимального отдела
бедра, находит нарушения укладки и захвата поля сканирования и отдаёт таблицу
результатов в формате автопроверки. Решение работает полностью локально
(офлайн), объясняет каждое найденное нарушение через геометрические сигналы и
визуализацию и укладывается в лимит времени с большим запасом
(~0,08 с/файл на CPU при лимите 3 мин/исследование).

## О проекте

**Назначение.** Врач-рентгенолог тратит время на разбор денситограмм, снятых с
нарушением протокола: перекошенная ось позвоночника, не захваченные гребни
подвздошных костей, украшения в поле кадра, неверная ротация бедра, неполное
поле сканирования. Columba отсеивает такие исследования автоматически: для
каждого файла выдаёт регион, бинарный класс качества, калибруемую вероятность
нарушения и перечень конкретных типов нарушений.

**Возможности:**

- определение анатомического региона и стороны бедра только по пикселям
  (без DICOM-тегов зоны и подсказок в именах файлов);
- пять типов нарушений из закрытого словаря: три для позвоночника
  («Некорректная укладка», «Не выровнена ось позвоночника», «Присутствуют
  посторонние предметы») и два для бедра («Некорректная укладка»,
  «Некорректная область интереса»);
- строка результата на **каждый** входной файл, включая попиксельные дубликаты
  и нечитаемые файлы — формат пригоден для автопроверки без постобработки;
- объяснимость: каждый вердикт сопровождается численными сигналами
  (угол оси, дефицит видимости гребней, координаты ориентиров), доступна
  визуализация поверх кадра (`POST /visualize`) и выгрузка DICOM SR;
- HTTP-сервис (FastAPI) с пакетной загрузкой ZIP-архива, веб-интерфейс,
  CLI — на выбор;
- полностью офлайн-инференс: ни одного внешнего сетевого вызова
  (проверяется тестом), фиксированный seed, воспроизводимые веса с
  контрольными суммами SHA-256.

**Ограничения:**

- решение калибровано под денситометр **GE Lunar Prodigy Advance** (софт
  18.41.005 и 18.50.082): физический размер пикселя зашит константами
  1,05 мм × 0,6 мм (в тегах его нет), эвристика региона опирается на
  стандартные ширины кадра 300/280/248 px. На снимках других аппаратов
  корректность не гарантируется;
- сторона бедра (левое/правое) определяется внутри пайплайна, но в выходную
  таблицу не выводится (не требуется форматом);
- чекер «Некорректная укладка» бедра требует весов CNN: без файла
  `hip_positioning_cnn.pt` этот тип нарушения не выставляется (см.
  [известные ошибки](#известные-ошибки-и-их-обработка));
- класс «Некорректная область интереса» обучен на единицах положительных
  примеров — порог выбран по PR-кривой, но статистическая надёжность этого
  класса ниже остальных;
- сопутствующие патологии (сколиоз, переломы, эндопротез) нарушением укладки
  не считаются и не детектируются: бедро с эндопротезом оценивается как
  обычное.

## Как работает решение

Принцип — не end-to-end чёрный ящик, а модульный пайплайн «детекция
анатомических ориентиров → геометрические правила»: критерии качества DXA
измеримы, размеченных данных мало, а объяснимость — прямое требование. Каждый
чекер отдаёт монотонный скор («больше — хуже»), бинарный флаг по
откалиброванному порогу и статус `ok`/`not_evaluated` с причиной.

### Схема пайплайна

```
DICOM-файлы
   │ 1. ингест: pydicom, нормализация яркости, статус чтения
   │ 2. хэш пикселей: дубликаты обсчитываются один раз (результат тиражируется)
   ▼
Регион и сторона (эвристика по ширине кадра + CNN-арбитраж)
   ├─ позвоночник ─► чекеры: ось │ укладка │ посторонние предметы
   └─ бедро       ─► чекеры: укладка/ротация (CNN) │ область интереса (правило)
   ▼
Агрегация: quality_class = ИЛИ по флагам, quality_prob, маппинг в словарь
   ▼
Валидатор формата ─► строка на каждый файл (CSV / JSON / DICOM SR)
```

### Предобработка

- Чтение DICOM через `pydicom` (`dicom_io.py`); битые файлы получают статус
  `Failure` и остаются в выходной таблице.
- Нормализация яркости с учётом тегов представления.
- Pixel spacing в тегах отсутствует — используется фиксированный размер
  пикселя из документации аппарата: **1,05 мм по Y и 0,6 мм по X**
  (`config.PIXEL_SPACING_MM`). Пиксель анизотропный, поэтому все расчёты
  углов и расстояний ведутся с поправкой на анизотропию, а входы CNN
  ресемплируются к изотропному пикселю.
- Для CNN-веток кадр приводится к квадрату 224×224 letterbox'ом (без
  искажения пропорций), правое бедро отражается к виду левого.
- Пороги протокола пересчитаны в пиксели через физический масштаб:
  «3 см» по вертикали ≈ 28,6 px, «2 см» по горизонтали ≈ 33,3 px.

### Модели и чекеры

**Регион и сторона** (`regions.py`, `region_cnn.py`, арбитраж в
`inference.py`). Первична эвристика по ширине кадра (300 px — позвоночник,
280/248 px — бедро; сторона — по положению таза), ResNet18 (3 класса)
подтверждает её. Расхождение пишется в лог; на кадрах 248 px, где эвристика
сторону не даёт, сторона берётся из CNN; на нестандартной ширине приоритет у
CNN. Внутри одного исследования стороны пары бёдер разводятся попарно. На
обучающей выборке обе ветки совпали на 100% файлов.

**Позвоночник** (`spine_checkers.py`) — три чекера:

| Чекер | Выходная метка | Решающий сигнал |
|---|---|---|
| `spine_axis` | «Не выровнена ось позвоночника» | Центры тел позвонков находит классический детектор (DP-хребет + максимумы детрендированного профиля); угол — робастный наклон (Theil–Sen) срединной линии костной колонны между крайними центрами; порог 4,0° от вертикали кадра |
| `spine_positioning` | «Некорректная укладка» | Дефицит видимости гребней подвздошных костей в нижней полосе кадра (захват поля) |
| `spine_objects` | «Присутствуют посторонние предметы» | Rule-based детектор «тонкое яркое на тёмном фоне» (цепочки, клипсы); вероятность обученной CNN-ветки дописывается в сигналы |

Сколиоз при корректно расположенной оси — норма: кривизна между крайними
позвонками не штрафуется.

**Бедро** (`hip_landmarks.py`, `hip_checkers.py`) — два чекера:

| Чекер | Выходная метка | Решающий сигнал |
|---|---|---|
| `hip_positioning` | «Некорректная укладка» | CNN (ResNet18, обучена в Colab на кропах бедра) — вероятность нарушения укладки/ротации; порог 0,8844 (best-F1 на out-of-fold предсказаниях train). Геометрические ориентиры (вертелы, шейка, ось диафиза) остаются в сигналах для объяснимости |
| `hip_roi` | «Некорректная область интереса» | Rule-based проверка полноты поля сканирования; решающий сигнал — высота кадра, порог `rows_px ≤ 207` |

**Реестр весов.** Четыре файла весов (~136 МБ суммарно) в git не хранятся:
контрольные суммы, команды воспроизведения и ссылки на скачивание — в
[weights_registry.json](weights_registry.json) (машиночитаемый источник
истины) и [WEIGHTS.md](WEIGHTS.md) (человекочитаемая проекция). Загрузка и
проверка: `uv run python -m columba.weights download && uv run python -m
columba.weights verify`.

### Постобработка и агрегация

`aggregate.py` собирает строку результата из флагов чекеров:

1. `quality_class` = логическое ИЛИ по флагам чекеров региона
   (**конвенция: 1 = нарушение, 0 = качественное исследование**;
   полярность зафиксирована юнит-тестом);
2. `violation_type` = типы сработавших чекеров, отображённые в закрытый
   словарь (`config.OUTPUT_LABELS`, строки сверяются посимвольно тестом),
   несколько типов — через «;»;
3. `quality_prob` = максимум по сигмоидам скоров чекеров вокруг их порогов
   (масштаб — std скора чекера на train). Скрипт `columba.calibrate` строит
   поверх честных out-of-fold скоров Platt-калибровку и три варианта порога
   класса с метриками — его отчёт служит основанием для выбора рабочей точки;
4. если чекер не смог оценить файл (`not_evaluated`), используется честный
   fallback: для бедра — априорная вероятность `HIP_PRIOR_QUALITY_PROB`
   (доля нарушений бедра на train, 34/122 ≈ 0,28) при `quality_class = 0`;
5. валидатор (`submission.validate_submission`) проверяет каждую строку:
   словарные значения, диапазон вероятности, согласованность класса и
   вероятности, строку на каждый входной файл.

### Промежуточные эксперименты

Ключевые развилки проекта решались измерением, а не интуицией. Что было
проверено и что из этого вошло в рантайм:

- **Ось позвоночника: прямая против срединной линии.** Исходный план — угол
  прямой «верхний центр тела → нижний центр» — не коррелировал с экспертной
  меткой (AUC ≈ 0,5). Рабочим стал робастный наклон Theil–Sen срединной линии
  костного силуэта колонны; порог 4,0° откалиброван на разметке (стартовые 5°
  из протокола не ловили ни одного позитива train). Итоговый OOF AUC — 0,759
  [0,579; 0,916].
- **U-Net против классического детектора позвонков.** U-Net кейпоинтов
  обучена (`spine_keypoint_net.py`), но в рантайм не включена: классический
  детектор не уступил, а объясним лучше. U-Net осталась артефактом сравнения
  и материалом проверок устойчивости (`spine_unet_check.py`: маскирование
  углов, салиенси).
- **Посторонние предметы: правило против CNN.** По вложенной CV rule-based
  детектор точнее обученной CNN (OOF AUC 0,820 против 0,772) — в рантайме
  решает правило, CNN лишь дописывает вероятность в сигналы. После проверки
  на реальном тестовом файле в правило добавлены верхние границы
  площади/диагонали компоненты: рёберный край перестал ложно флаговаться как
  металл.
- **Укладка позвоночника: какой сигнал разделяет классы.** Смещение цепочки
  позвонков и отступ «3 см» на train классы не разделяют — они только
  логируются; решающим стал дефицит видимости гребней подвздошных костей
  (OOF AUC 0,997 [0,986; 1,0]).
- **Укладка бедра: геометрия против CNN.** Геометрические сигналы по
  кейпоинтам статистически неотличимы от случайного (nested group-CV OOF AUC
  0,564 [0,452; 0,684]), CNN на тех же метках — 0,765. Решает CNN, геометрия
  оставлена в сигналах. Красный флаг «CNN проксирует версию софта» проверен и
  не подтверждён (AUC по версии 0,426 против 0,537 у метки).
- **Область интереса бедра: одно правило вместо модели.** При шести
  train-позитивах многомерная логрегрессия — гарантированное переобучение;
  выбран единственный самый сильный сигнал (высота кадра), nested CV AUC
  0,931 [0,791; 1,0], порог `rows_px ≤ 207` по best-F1 (precision 0,8 /
  recall 0,667). Расширение правила отступами по X и сверху проверено и
  отклонено по числам: precision ≈ 9%.
- **Калибровка вероятности: где брать скоры.** Прямая калибровка на
  train-скорах деплоя завышена утечкой: CNN бедра, обученная на всём train,
  на нём же даёт AUC 0,991 против честных 0,749 out-of-fold. Калибровка
  построена только на OOF-скорах; Platt выбран против изотоники по Brier на
  val (0,1437 против 0,1507).
- **Устойчивость к маскированию.** Чёрные прямоугольники по краям бёдер —
  постобработка лаборанта, не признак нарушения. CNN-ветки обучены с
  аугментацией случайного маскирования углов; устойчивость подтверждена
  салиенси-проверками и регрессионными тестами (включая реальные кейсы с
  эндопротезами и кадры 248 px).
- **Синтетика как проверка чувствительности.** Повороты качественных снимков
  на 6–10° ловятся чекером оси в 34/36 случаев (повороты 1–2° дают 3/24
  ложных флагов); кропы с обрезанными гребнями поднимают флаг укладки в 6/12.
  Валидация при этом — только на реальных экспертных метках.
- **Сверка с комментариями врачей.** Чек-лист из 54 снимков со свободными
  комментариями: 77,8% вердиктов пайплайна согласуются; все 12 расхождений
  разобраны вручную — это известные спорные места разметки, а не новый класс
  дефектов пайплайна.

### Работа с дисбалансом классов

В размеченной выборке 249 уникальных изображений, из них 72 с нарушением, а
по отдельным типам счёт идёт на единицы (у «Некорректной области интереса» —
6 позитивов train / 1 val). Дисбаланс обрабатывается на каждом уровне:

- **сплит и валидация** — стратифицированный сплит по исследованиям
  (пациентам) после дедупликации, без утечки; пороги и метрики — только через
  групповую вложенную CV (out-of-fold), никогда на данных, участвовавших в
  обучении;
- **функция потерь** — `BCEWithLogitsLoss` с `pos_weight = n_neg / n_pos` во
  всех бинарных CNN-ветках (`spine_objects_cnn`, `hip_positioning_cnn`);
- **oversampling** — `WeightedRandomSampler` выравнивает классы в каждом
  батче при обучении CNN укладки бедра (29 позитивов на 122 train — обе меры
  применяются одновременно);
- **rule-based вместо ML для сверхредких классов** — `hip_roi` с шестью
  позитивами не обучается, а проверяется одним геометрическим правилом,
  откалиброванным по PR-кривой: правилу достаточно единиц примеров как
  калибровочных точек;
- **синтетические примеры** — повороты, вставка металла, кропы поля
  (`spine_synth.py`) расширяют редкие классы для проверки чувствительности
  порогов (в валидационные метрики синтетика не входит);
- **пороги классов** — не 0,5 по умолчанию, а best-F1 на OOF-предсказаниях
  train для каждого чекера; отдельно рассчитан recall-ориентированный вариант
  (F2), дающий recall 1,0 ценой precision ≈ 0,31–0,33;
- **честные приоры** — когда сигнал недоступен, вместо нуля подставляется
  доля нарушений класса на train (`HIP_PRIOR_QUALITY_PROB`);
- **метрики по классам отдельно** — Macro-F1 и по-чекерные AUC/F1 с 95% ДИ
  кластерным бутстрэпом по исследованиям, чтобы редкие классы не тонули в
  среднем.

### Достигнутое качество

Оценки по вложенной групповой CV (out-of-fold, 95% ДИ кластерным бутстрэпом
по исследованиям):

| Чекер | OOF AUC [95% ДИ] |
|---|---|
| Ось позвоночника (`spine_axis`) | 0,759 [0,579; 0,916] |
| Укладка позвоночника (`spine_positioning`) | 0,997 [0,986; 1,0] |
| Посторонние предметы (`spine_objects`, правило) | 0,820 [0,685; 0,936] |
| Укладка бедра (`hip_positioning`, CNN) | 0,765 |
| Область интереса бедра (`hip_roi`) | 0,931 [0,791; 1,0] |

Интегральная бинарная оценка «есть нарушение» после Platt-калибровки на
честных OOF-скорах: ROC-AUC 0,724 [0,651; 0,792] на train и 0,806
[0,627; 0,943] на val; бинарная F1 при рекомендованном пороге best-F1 —
0,589 train / 0,522 val. Полный прогон 499 файлов на CPU — ~0,08 с/файл.

| Артефакт | Что содержит | Команда |
|---|---|---|
| `artifacts/manifest.parquet`, `targets.csv`, `split.json`, `anomalies.md` | реестр файлов, таргеты из критериев, сплит, лог матчинга | `uv run python main.py` |

## Системные требования и зависимости

**Железо.** Инференс работает на CPU (~0,08 с/файл — лимит «3 мин на
исследование» выполняется с запасом на порядки); GPU не обязателен.
Оперативной памяти достаточно 4 ГБ. Диск: ~2 ГБ на окружение (CPU-вариант
PyTorch) или ~8 ГБ (вариант с CUDA), плюс ~140 МБ весов. Поддерживаются
Linux, macOS (включая Apple Silicon/MPS) и Windows; ускорение CUDA — на
серверах с NVIDIA GPU.

**Софт:**

- Python **3.12** и менеджер пакетов [uv](https://docs.astral.sh/uv/)
  (для локального запуска), или
- Docker 24+ (для контейнерного запуска; для GPU — драйвер NVIDIA и
  `nvidia-container-toolkit`).

**Зависимости** (полный список с версиями — [pyproject.toml](pyproject.toml)
и lock-файл [uv.lock](uv.lock)): pydicom, highdicom, numpy, pandas, pyarrow,
openpyxl, torch, torchvision, matplotlib, fastapi, uvicorn, python-multipart;
для разработки — pytest, httpx. Облачные API не используются: инференс не
делает внешних сетевых вызовов.

## Установка и запуск локально

```bash
git clone https://github.com/exxyyf/columba.git && cd columba
uv sync                                    # создаст .venv с Python 3.12 и зависимостями
uv run python -m columba.weights download  # скачать веса по ссылкам из weights_registry.json
uv run python -m columba.weights verify    # сверить размеры и SHA-256
```

Если хост без интернета, скачайте четыре файла весов по ссылкам из
[WEIGHTS.md](WEIGHTS.md) на любой машине, положите их в `artifacts/models/` и
выполните только `verify`.

Запуск сервиса:

```bash
uv run uvicorn columba.service:app --host 0.0.0.0 --port 8000
```

Проверка: `curl http://localhost:8000/health` и веб-интерфейс на
<http://localhost:8000/>.

Пакетный прогон без HTTP (каталог любой структуры — как закрытый тест):

```bash
uv run python -m columba.submit <каталог_с_dcm> submission.csv
```

## Сборка и запуск в Docker

Веса скачиваются **на хосте** (см. выше) и монтируются в контейнер только для
чтения — в образ они не запекаются, в рантайме ничего не скачивается.

```bash
# образ для сервера с NVIDIA GPU (по умолчанию)
docker build -t columba:gpu .
docker run --rm --gpus all -p 8000:8000 \
  --mount type=bind,source="$(pwd)/artifacts",target=/app/artifacts,readonly \
  columba:gpu

# облегчённый CPU-образ (локальная проверка, CI)
docker build --build-arg TORCH_VARIANT=cpu -t columba:cpu .
docker run --rm -p 8000:8000 \
  --mount type=bind,source="$(pwd)/artifacts",target=/app/artifacts,readonly \
  columba:cpu
```

В PowerShell путь для `--mount` задаётся так:

```powershell
$artifactsPath = (Resolve-Path -LiteralPath artifacts).Path
docker run --rm -p 8000:8000 --mount "type=bind,source=$artifactsPath,target=/app/artifacts,readonly" columba:cpu
```

При старте контейнер проверяет размеры и SHA-256 всех весов по
`weights_registry.json` и завершает работу с ошибкой, если файл отсутствует
или повреждён. После запуска на GPU-сервере проверьте `GET /health`: поле
`device` должно быть `cuda`. Подробное руководство со сценариями отказов —
[docs/deployment.md](docs/deployment.md).

## API

Сервис — тонкая HTTP-обёртка над тем же пайплайном, что и CLI: никакой
отдельной логики инференса в нём нет. Интерактивная спецификация OpenAPI —
на `/docs` запущенного сервиса.

| Метод и путь | Назначение |
|---|---|
| `GET /health` | статус, устройство инференса (`cpu`/`cuda`/`mps`), seed, наличие каждого файла весов |
| `POST /predict` | плоский список DICOM-файлов (multipart-поле `files`, повторяется на каждый файл); опциональное поле `paths` — относительные пути для восстановления структуры папок |
| `POST /predict/zip` | ZIP-архив каталога с исследованиями — **рекомендованный способ пакетной проверки** |
| `POST /visualize` | один DICOM-файл → PNG с ориентирами и результатами чекеров |
| `GET /` | веб-интерфейс |

`POST /predict` и `POST /predict/zip` по умолчанию возвращают CSV
(`text/csv`) ровно в формате сабмита; с `?format=json` — те же строки в JSON:

```json
{"rows": [...], "n_files": 3, "elapsed_seconds": 0.41}
```

`POST /visualize` с `?format=json` возвращает регион, сторону и результаты
чекеров структурированными данными вместо PNG.

**Пакетная проверка** (структура папок исследований в архиве сохраняется —
это включает парное определение стороны бедра внутри исследования):

```bash
zip -r test_data.zip <каталог_закрытого_теста>
curl -F "file=@test_data.zip" "http://localhost:8000/predict/zip" -o submission.csv
```

Плоский список файлов и JSON-ответ:

```bash
curl -F "files=@CR000000.dcm" -F "files=@CR000001.dcm" \
  "http://localhost:8000/predict?format=json"
```

Визуализация одного файла:

```bash
curl -F "file=@CR000000.dcm" "http://localhost:8000/visualize" -o overlay.png
```

Ошибки возвращаются кодом 400 с человекочитаемой причиной в поле `detail`
(нет DICOM-файлов во входе, битый архив, недопустимые пути). Полный разбор —
в разделе [известных ошибок](#известные-ошибки-и-их-обработка).

## Формат входных и выходных данных

### Вход

DICOM-файлы (`*.dcm`) денситометра GE Lunar Prodigy Advance: поясничный отдел
позвоночника или проксимальный отдел бедра. Каталог (или ZIP) может быть
плоским или содержать папки исследований — структура используется только для
парного разведения сторон бёдер, никакие теги зоны и суффиксы имён файлов не
требуются: регион определяется по изображению. Попиксельные дубликаты
допустимы — каждый файл получает свою строку результата (дубликаты
обсчитываются один раз, результат тиражируется).

### Выход

CSV (UTF-8) со строкой на **каждый** входной файл:

| Колонка | Тип | Описание |
|---|---|---|
| `file_name` | строка | путь файла относительно корня входного каталога/архива |
| `anatomical_region` | строка | ровно одно из двух значений словаря: «Поясничный отдел позвоночника» или «Проксимальный отдел бедра» |
| `quality_class` | 0/1 | **1 = есть нарушение**, 0 = качественное исследование |
| `quality_prob` | [0; 1] | вероятность нарушения (согласована с классом по порогу 0,5) |
| `violation_type` | строка | типы нарушений из закрытого словаря через «;»; пусто, если нарушений нет |

Словарь `violation_type` (строки воспроизводятся посимвольно; допустимые
типы привязаны к региону):

- позвоночник: «Некорректная укладка», «Не выровнена ось позвоночника»,
  «Присутствуют посторонние предметы»;
- бедро: «Некорректная укладка», «Некорректная область интереса».

Пример:

```csv
file_name,anatomical_region,quality_class,quality_prob,violation_type
study_001/CR000000.dcm,Поясничный отдел позвоночника,1,0.8123,Не выровнена ось позвоночника;Присутствуют посторонние предметы
study_001/CR000001.dcm,Проксимальный отдел бедра,0,0.2787,
```

Дополнительно выводятся отладочные колонки (`relative_path`, `study_folder`,
`read_status`, `dedup_group_id`, `sop_instance_uid`) — автопроверке лишние
колонки не мешают, а разбор результатов упрощают. Альтернативный формат
вывода — DICOM SR (Comprehensive SR) на файл: `uv run python -m
columba.dicom_sr <файл|каталог>`.

## Веб-интерфейс

На `/` запущенного сервиса доступен интерфейс без установки чего-либо
дополнительно: загрузка отдельных файлов, папки или ZIP (структура папок
сохраняется), таблица результатов со сводкой по пачке, визуализация
ориентиров и чекеров по клику на строку, экспорт CSV. Интерфейс проходит
аудит доступности WCAG AA (проверено axe-core). Пошаговое описание — в
[docs/user_guide.md](docs/user_guide.md).

В `interface/` лежит отдельный вспомогательный просмотрщик обучающего
датасета (TypeScript/Express) — это dev-инструмент команды, для проверки
решения он не нужен.

## Обучение и дообучение моделей

Инференсу обучение не требуется — достаточно скачать веса. Полная процедура
воспроизведения обучения — [docs/training.md](docs/training.md); кратко:

1. Положить обучающую выгрузку в `data/` и собрать датасет:
   `uv run python main.py` (манифест, дедупликация, таргеты из критериев
   разметки, стратифицированный сплит по пациентам, EDA).
2. Обучить локальные модели: `uv run python -m columba.train_region_cnn`
   (регион/сторона), `uv run python -m columba.spine_objects_cnn`
   (CNN-ветка предметов), `uv run python -m columba.spine_keypoint_net`
   (U-Net, артефакт сравнения).
3. CNN укладки бедра: экспортировать обезличенный датасет кропов
   (`uv run python -m columba.hip_export`) и прогнать
   [notebooks/hip_positioning_cnn.ipynb](notebooks/hip_positioning_cnn.ipynb)
   в Google Colab (T4, ≤15 минут), скачать веса и OOF-предсказания в
   `artifacts/`.
4. Перекалибровать пороги и собрать отчёты: `spine_eval`, `hip_eval`,
   `stage3_eval`, `calibrate`.
5. Обновить SHA-256 и размеры в `weights_registry.json`, прогнать
   `uv run pytest`.

Seed зафиксирован (42) по всему пайплайну; вся случайность обучения
детерминирована с точностью до библиотечной недетерминированности бэкендов.

## Известные ошибки и их обработка

Пайплайн спроектирован так, чтобы одиночная проблема не роняла батч и не
ломала формат выхода:

| Ситуация | Поведение решения |
|---|---|
| Нечитаемый/битый DICOM | файл не выбрасывается: получает `read_status = Failure`, в сабмите остаётся строка с `quality_class = 0`, `quality_prob = 0.0`, пустым `violation_type` |
| Исключение чекера на одном файле | статус `not_evaluated` с причиной только для этого файла; остальные файлы батча считаются дальше |
| Во входе нет `*.dcm` | HTTP 400 «во входных данных нет файлов .dcm» |
| Битый ZIP-архив | HTTP 400 «не удалось распаковать zip» |
| Небезопасные пути (абсолютные, `..`) в архиве или поле `paths` | элементы архива молча отфильтровываются; недопустимый `paths` — HTTP 400 |
| `files` и `paths` разной длины в `/predict` | HTTP 400 |
| Одинаковые имена файлов в одной загрузке | автоматическое разведение суффиксом `__N`, ни один файл не перезаписывается и не теряется |
| Кадр нестандартной ширины и нет весов region CNN | регион честно `unknown` в отладочных колонках; в сабмит идёт fallback-значение региона (формат не нарушается) |
| Отсутствует файл весов | сервис не падает — честная деградация: без `region_cnn.pt` работает чистая эвристика; без `spine_objects_cnn.pt` детектор предметов остаётся rule-based (это и есть основной путь); без `hip_positioning_cnn.pt` чекер укладки бедра отключается (`not_evaluated`), агрегатор откатывается на `hip_roi` и приор. Матрица деградации по каждому файлу — в [WEIGHTS.md](WEIGHTS.md) |
| Повреждённые веса при старте контейнера | `weights verify` завершает контейнер с ошибкой до запуска сервиса (ошибка видна в логах контейнера) |
| `NaN` в численных сигналах | в JSON-ответах сериализуется как `null` |

Диагностика: `GET /health` показывает устройство инференса и наличие каждого
файла весов; отладочные колонки сабмита (`read_status`, `dedup_group_id`)
позволяют проследить судьбу каждого файла.

## Тестирование

```bash
uv run pytest
```

346 тестов покрывают: инварианты данных (дедупликация, отсутствие утечки
между train/val по изображениям и пациентам, пропуски разметки, не
превратившиеся в нули), выходной формат (посимвольная сверка строк словаря,
полярность `quality_class = 1 → нарушение`, строка на каждый файл,
согласованность класса и вероятности), устойчивость к условиям закрытого
теста (регион и сторона определяются верно при вырезанных тегах зоны и
нейтральных именах файлов), API (все эндпоинты, коллизии имён, zip-slip),
честную деградацию без весов и офлайн-гарантию (инференс не импортирует
сетевой код). Для полного прогона нужны веса ([WEIGHTS.md](WEIGHTS.md)) и
локальные данные обучения.
